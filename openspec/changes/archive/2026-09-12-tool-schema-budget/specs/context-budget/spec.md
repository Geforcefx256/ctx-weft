# context-budget

## Purpose

定义上下文预算的完整口径契约：工具面（名称 + 描述 + 入参 schema）成本在装配预留与循环增量估算两处入账，动态工具集变化可感知，发送前超限不硬拒而走收紧与压缩，偏差可观测。

## ADDED Requirements

### Requirement: 装配预算含工具面预留

装配裁剪的内容预算 SHALL 等于有效窗口减去当前工具面的 token 估算（工具名 + 描述 + 入参 schema 序列化，按当次装配的可用能力快照现算）。预留值 SHALL 随工具集变化：动态加载/pin 新工具后再次装配，预留增长、内容可用预算相应减少。超限裁剪的对象是内容块；工具声明数组 MUST 维持不裁剪的既有语义（声明完整性），预算压力由预留承担。

#### Scenario: 大 schema 工具入账

- **WHEN** 注册一个入参 schema 很大的工具后装配
- **THEN** 装配预留较此前明显增长，内容块可用预算相应缩小；预留值可从装配产物 metadata 读取

#### Scenario: 同名工具 schema 增长同样入账

- **WHEN** 某工具名称不变，但其 description 或入参 schema 显著增长后再次装配/请求
- **THEN** 工具面指纹变化、预留与估算相应增长（指纹 MUST 覆盖与估算一致的规范化工具定义，仅名称集合不构成指纹）

#### Scenario: 工具声明不被裁剪换预算

- **WHEN** 预算紧张触发裁剪
- **THEN** 裁剪作用于内容块，最终请求的工具声明与能力快照一致

### Requirement: 循环估算追踪工具面变化

循环内增量估算（真实基线 + 新增消息）在工具面指纹变化时 SHALL 把工具面增量计入（当次工具面估算 − 上次发送时的工具面估算）；指纹不变时估算行为与既有纯消息增量逐字节一致。工具面变化后，估算 MUST 在变化后的首次发送前生效（防 max_tokens 虚高）。

#### Scenario: pin 大 schema 后估算立即增长

- **WHEN** act 循环中段运行期 pin 一个大 schema 工具，工具面指纹变化，下一次请求发送
- **THEN** 该请求的 prompt 估算较此前增量路径明显增长（含工具面增量），max_tokens 按新估算收紧

#### Scenario: 工具面不变时行为不变

- **WHEN** 工具面在多轮间未变化
- **THEN** 增量估算仅含新增消息，结果与改造前一致（对照断言）

### Requirement: 发送前超限不硬拒

发送关口 MUST NOT 以 token 估算超限为由拒绝请求。估算超出有效窗口时 SHALL：max_tokens 按含工具面的估算收紧（既有动态输出计算）、留下显式超限留痕（WARNING 级）、由既有压缩比例机制在后续轮触发压缩。

#### Scenario: 超限请求照发且输出收紧

- **WHEN** 含工具面后估算超出有效窗口
- **THEN** 请求正常发出、max_tokens 不超过按剩余空间收紧的值、超限留痕可检索；后续轮按既有机制触发压缩

### Requirement: 偏差留痕

估算与实际 usage 的既有回喂链路之上，SHALL 保留工具面分项的偏差留痕（预留值、指纹、实测 prompt tokens 同现于日志/事件字段），供校准与回归分析。

#### Scenario: 偏差可归因

- **WHEN** 分析某轮估算与实测的偏差
- **THEN** 可从留痕分辨工具面预留的占比与指纹变化时点
